# План разработки на 2 недели

Актуально на 2026-04-23.

## Неделя 1 - стабилизация MVP

1. Зафиксировать canonical API frontend/backend.
2. Проверить запуск с чистой БД: migrate, seed, login, создание заявки.
3. Проверить полный UI-сценарий merge/close approval после выравнивания API.
4. Доделать отображение статуса `MERGED` во всех списках и фильтрах.
5. Проверить роли USER/EMPLOYEE/MANAGER/ADMIN на реальных сценариях.
6. Обновить demo seed под компанию: IT, склад, маркетплейсы, 1С.
7. Подготовить release checklist для директора.
8. Проверить ручной backup на сервере и включить `BACKUP_ENABLED=true`.
9. Проверить `email:smoke`, затем `email:sync` на реальном Яндекс-ящике.
10. Проверить `email:reply-smoke` и `knowledge:smoke`.

## Неделя 2 - продуктовая пригодность

1. Email hardening: реальный Яндекс-пилот для IMAP/SMTP, политика обработанных писем, папка по умолчанию.
2. Email reply production: журнал исходящих, retry, UI-кнопка ответа из заявки.
3. База знаний hardening: шаблоны ответов, версии статей, улучшение UX поиска.
4. Backup: добавить резервирование uploaded-файлов и регламент restore на тестовой базе.
5. Права папок через команды исполнителей.
6. Статистика по заявкам и исполнителям для руководителя.

## Правило приоритета

Если остаётся мало времени, приоритет такой: запуск и логин, создание заявки, очередь, комментарии, вложения, справочники, merge/close, ручной backup, email smoke/sync/reply-smoke, база знаний smoke, потом hardening.
