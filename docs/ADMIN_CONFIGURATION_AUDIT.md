# Аудит административной настраиваемости

Актуально на 2026-07-19.

Документ фиксирует, какие параметры Office ServiceDesk уже можно менять через API администратора, какие параметры намеренно остаются на сервере и чего не хватает для адаптации продукта под разные компании.

## Итог

Основная модель очередей уже не привязана к конкретной компании: `ADMIN` может создавать папки, команды, типы, подтипы и сущности, связывать команды с несколькими папками и назначать активных исполнителей. Демонстрационные названия про IT, 1С и склад находятся в seed-данных, а не в runtime-логике.

Добавлен singleton ProductSettings для основных несекретных параметров компании. Название портала/компании, приветствие, locale, timezone, приоритет и активная папка по умолчанию управляются через admin API. Безопасный read endpoint публичен, чтобы брендировать Login/Register до входа, но не содержит `id`, timestamps или служебных данных. Логотип, дополнительные поля и не секретные параметры email-маршрутизации остаются следующими P1-задачами. Секреты и сетевые параметры нельзя переносить в такую админку.

## Что уже настраивает ADMIN

| Область | Возможности |
| --- | --- |
| Пользователи | создание, роль `ADMIN / AGENT / REQUESTER`, блокировка/активация, смена пароля |
| Папки | CRUD, активность, порядок, доступ команд |
| Команды | CRUD, несколько папок, состав из активных `ADMIN / AGENT` |
| Типы и подтипы | CRUD, привязка к папкам, контроль совместимости `подтип -> тип -> папка` |
| Сущности | CRUD и использование в классификации заявок |
| Автоматизация | CRUD правил, порядок, включение, условия, действия, dry-run и журнал запусков |
| SLA | CRUD политик и dry-run; если SLA не нужен компании, политики можно не создавать |
| Email | диагностика и outbox, ручной retry; отправка и intake включаются оператором сервера |
| Шаблоны ответов | личные и общие шаблоны, CRUD для исполнителей и администратора |
| База знаний | статьи, категории строкой, публикация и CRUD |
| Freshdesk | dry-run, импорт, история запусков, source health |
| Общие настройки | название портала/компании, приветствие, locale, timezone, default priority и default folder |

## Что остаётся серверной настройкой

Эти параметры являются частью инфраструктуры и безопасности. Их нужно хранить в `.env`/secret storage и менять с перезапуском сервиса, а не через обычный admin UI:

- `DATABASE_URL`, `JWT_SECRET`;
- `CORS_ORIGINS`, `TRUST_PROXY`, rate limits;
- SMTP/IMAP логины и пароли, Freshdesk API key;
- `UPLOADS_DIR`, `BACKUP_DIR`, лимиты и расписание backup;
- feature flags реальной email-отправки, intake и worker;
- `PORTAL_BASE_URL` как deployment URL.

## CORS

- Разрешаются только точные frontend origins из `CORS_ORIGINS`.
- `CORS_ORIGIN` является single-origin alias и используется только при пустом `CORS_ORIGINS`.
- `*` намеренно запрещён.
- Значение содержит только схему, хост и необязательный порт, без пути: `https://desk.example.ru`.
- Запросы без `Origin` разрешены для health checks, CLI и server-to-server интеграций; браузерный origin обязан находиться в allowlist.
- Случайный домен Cloudflare Tunnel нужно явно добавить и затем перезапустить backend. Новый домен следующего tunnel-сеанса автоматически не разрешается.

## Исправленные риски целостности

- Нельзя удалить папку, пока она доступна хотя бы одной команде через multip folder mapping.
- Нельзя создать подтип с папкой, несовместимой с папкой его типа.
- Нельзя создать SLA policy с несовместимыми folder/type/subtype.
- В команду нельзя добавить заявителя или отключённого исполнителя.
- Нельзя назначить на заявку отключённого пользователя или роль, не являющуюся исполнителем/администратором.
- Automation rule проверяет исполнителей при сохранении, а не только при выполнении.
- Публичные справочники не раскрывают заявителям состав команд, email исполнителей и служебные счётчики; полный payload доступен только admin API.

## Что ещё требуется

### P1: до универсального продукта

1. Добавить логотип/брендинг поверх существующего `ProductSettings`, не сохраняя бинарные данные прямо в singleton.
2. Добавить настраиваемые теги и правила их назначения.
3. Добавить конструктор дополнительных полей заявки и настройку обязательности по типу/папке.
4. Вынести не секретные email defaults (`folder/type/subtype/entity`) из env в валидируемые настройки с delete blockers.

### P2: расширенная адаптация

1. Отдельные CRUD-категории для базы знаний и шаблонов вместо свободного текста.
2. Расширить automation событиями изменения статуса, назначения и комментария.
3. Добавить business hours/праздничные календари только если компания вернёт SLA в scope.
4. Добавить аудит изменений общих настроек и историю версий форм.

## Правило для seed

`prisma/seed.js` содержит русские демонстрационные папки и типы для разработки. На чистом production следует использовать `prisma:bootstrap-admin`, затем создавать справочники через админку или отдельный согласованный bootstrap-конфиг. Повторно использовать demo seed как конфигурацию конкретной компании не следует.
