# Роли и доступ

Актуально на 2026-04-25.

## Backend роли

- `ADMIN` - полный доступ, CRUD справочников, пользователи, удаление.
- `AGENT` - исполнительский сценарий: очередь, статусы, комментарии, база знаний, отчёты.
- `REQUESTER` - создаёт заявки и видит свои обращения.
- `VIEWER` - наблюдатель: только чтение, без изменений.

## Frontend capabilities

Frontend дополнительно использует capability matrix в `src/access.ts`: `tickets:read`, `tickets:create`, `tickets:update`, `directories:manage` и другие. Это удобно для меню и UI, но backend всё равно обязан проверять права на route/service уровне.

## Folder/team permissions

В ServiceDesk действует простая и жёсткая модель доступа к очередям:

- пользователь входит в одну или несколько команд;
- команда имеет доступ к одной или нескольким папкам;
- из этого набора папок считается рабочая область `AGENT`.

Дополнительно:

- `AGENT` всегда видит заявки, где он назначен исполнителем, даже если папка вне его штатной области;
- `REQUESTER` видит только заявки, где он автор;
- `VIEWER` остаётся read-only и не меняет данные;
- `ADMIN` не ограничен папками и командами.

## Видимость и действия по заявкам

- `ADMIN` читает, обновляет, назначает и удаляет без ограничений по папкам.
- `AGENT` читает заявку, если:
  - папка входит в доступные ему папки команды, или
  - он назначен исполнителем этой заявки.
- `AGENT` может менять статус заявки, если у него есть доступ к заявке как у исполнителя или через папку команды.
- `AGENT` может редактировать поля заявки и управлять исполнителями только для заявок из папок своей команды.
- `REQUESTER` создаёт заявку и видит только свои заявки.
- `REQUESTER` не имеет доступа к очереди исполнителей `/queue`.
- `VIEWER` читает данные в рамках текущей модели, но не изменяет их.

## Справочники

- Read-only `/api/servicedesk/*` доступен всем авторизованным.
- Admin CRUD `/api/servicedesk/admin/*` доступен только `ADMIN`.
- В командах настраиваются:
  - участники команды;
  - список папок, которые формируют очередь команды.

## Merge и закрытие

- Merge разрешён администраторам/исполнителям и назначенным исполнителям по логике сервиса.
- Close approval может сделать только назначенный исполнитель.
- `DONE` для UNION master с несколькими исполнителями блокируется до подтверждения всех исполнителей.

## Коротко о модели

`team -> folders -> queue visibility`, плюс fallback на `assignee` для точечной работы исполнителя с чужой папкой.
