# Roadmap ежедневной замены Freshdesk

Актуально на 2026-07-18.

## Цель релиза

ServiceDesk должен стать основным рабочим инструментом офиса на 50-60 сотрудников:

- заявки создаются из web и корпоративной почты;
- заявщик видит только свои обращения;
- исполнитель работает в доступных ему папках и берёт заявки в работу;
- администратор настраивает папки, типы, команды, пользователей и автоматизацию;
- вся переписка, файлы и действия сохраняются в карточке заявки;
- продукт восстанавливается из резервной копии после сбоя.

## Release candidate: готово в коде

- Три продуктовые роли: `ADMIN`, `AGENT`, `REQUESTER`.
- Три рабочих статуса: `NEW`, `IN_PROGRESS`, `DONE`.
- Inbox/очередь, серверный поиск, фильтры, сортировка и постраничная загрузка.
- Папки, команды и ограничения доступа исполнителей.
- Web-заявки, публичные ответы, внутренние заметки и вложения.
- Входящая Yandex IMAP почта с защитой от дублей и исходящая SMTP outbox с retry/lock.
- Номера заявок, слияние, совместное закрытие и timeline.
- Уведомления, шаблоны ответов, база знаний и правила автоматизации.
- Импорт Freshdesk с dry-run и идемпотентным повтором.
- Ежедневный backup PostgreSQL и каталога вложений с retention.
- Деактивация пользователя и отзыв активных JWT-сессий.
- Playwright smoke для ключевых ролей и мобильного просмотра.

## До пилота в офисе: обязательные внешние шаги

1. Развернуть локальную VM по `docs/LOCAL_VM_DEPLOY.md`.
2. Создать production `.env`, отдельного пользователя PostgreSQL и каталоги uploads/backups.
3. Проверить настоящий Yandex IMAP/SMTP через `email:yandex:check`.
4. Сначала включить email в dry-run, затем отдельно inbound, outbound и worker.
5. Выполнить backup и контрольный restore на тестовой БД/во временный каталог.
6. Импортировать 20-50 реальных заявок Freshdesk, проверить повторный импорт без дублей.
7. Провести UAT с администратором, 2-3 исполнителями и 5-10 заявщиками.
8. Перед выдачей доступа выполнить `npm run check:release`.

## Первые две недели эксплуатации

- Ежедневно проверять `/health`, email health/outbox, свободное место и наличие двух свежих backup.
- Собирать не пожелания “вообще”, а конкретные неудачные рабочие сценарии с номером заявки.
- Исправлять только блокирующие ошибки и непонятные действия; не менять одновременно роли и маршрутизацию.
- После стабильной недели сделать контрольный restore и зафиксировать версию релиза.

## После стабильного запуска

- Transactional event outbox для гарантированного запуска automation/notifications после создания заявки.
- Off-site копия backup и автоматическая проверка восстановления.
- Антивирусная проверка вложений (ClamAV) и журнал скачиваний.
- Импорт бинарных вложений Freshdesk, а не только metadata.
- Метрики процесса, централизованные логи и оповещение администратора о недоступности сервиса.
- Foundation интеграции с 1С через существующие external references.

## Осознанно не входит в первый рабочий релиз

- SLA, рабочие календари и эскалации.
- Управленческие отчёты.
- Публичный клиентский портал вне корпоративного контура.
- Горизонтальное масштабирование нескольких backend-инстансов.
