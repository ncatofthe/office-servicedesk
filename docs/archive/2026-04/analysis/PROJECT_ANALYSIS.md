# Project Analysis

## Общая архитектура

### Фронтенд (`task-manager-frontend`)
- **Стек**: React + TypeScript, Vite, Tailwind (используются CSS-переменные для монохромной темы), Zustand для локального состояния.
- **Структура**: страницы в `src/pages`, общие UI-компоненты в `src/components/ui`, контекст авторизации в `src/contexts/AuthContext.tsx`, HTTP-клиент + API-обёртки в `src/api`, типы в `src/types`.
- **Состояние и данные**: большинство страниц (Dashboard, Tasks, Kanban, Team, Finance, Reports) работают на мок-данных из `useAppStore.ts`; реальные запросы используются только в частях авторизации, уведомлений и обзора задач (reviews). Нет глобального запроса задач/пользователей/финансов с бэкенда.
- **Маршрутизация**: React Router, защищённые роуты через `ProtectedRoute` (проверка токена в `AuthContext`).
- **UI**: набор карточек (KPI, TaskCard, ChartCard, UserCard, AvatarGroup, Modal и др.) со стилизацией через utility-классы. Логин/регистрация имеют тёмную тему, остальные страницы — светлый монохром.

### Бэкенд (`task-manager-backend`)
- **Стек**: Express, Prisma (PostgreSQL), JWT авторизация, bcrypt, multer (загрузка файлов), cors/helmet/morgan.
- **Структура**: контроллеры, сервисы и роуты по доменам (`tasks`, `users`, `auth`, `comments`, `files`, `reviews`, `notifications`, `finance`, `dashboard`, `reports`).
- **Основные эндпоинты**:
  - `POST /api/auth/login`, `POST /api/auth/register`, `GET /api/auth/me`, `POST /api/auth/logout`.
  - `GET /api/users`, `GET/PUT/DELETE /api/users/:id` (создание через `auth/register` для USER или администратором).
  - `GET/POST/PUT/DELETE /api/tasks`, `GET /api/tasks/:id`, `PATCH /api/tasks/:id/status`, `POST/DELETE /api/tasks/:id/assignees`, вложенные комментарии/вложения через `/api/comments`, `/api/files`.
  - `GET /api/reviews`, `PATCH /api/reviews/:id` (подтверждение/отклонение задач на выплату).
  - `GET /api/notifications`, `PATCH /api/notifications/:id/read`.
  - `GET/POST /api/transactions`, `GET/POST/PATCH/DELETE /api/accounts`, `GET /api/dashboard`, `GET /api/reports`.
- **Модели данных (Prisma)**: `User`, `Task` (+ `TaskAssignee`, `TaskComment`, `TaskAttachment`, `TaskReview`, `TaskHistory`), `Account`, `Transaction`, `Notification`. Статусы задач: `NEW`, `IN_PROGRESS`, `REVIEW`, `DONE`, `POSTPONED`; приоритеты: `LOW|MEDIUM|HIGH|URGENT`.
- **Бизнес-логика**: сервисы проверяют роли (ADMIN/MANAGER/EMPLOYEE/FINANCE/VIEWER), ведут историю изменений задач, формируют уведомления, агрегации для дашборда и отчётов.

### Взаимодействие фронтенда и бэкенда (сейчас)
- Авторизация использует реальные API (`authApi.login/register/getMe/logout`) с JWT в `localStorage`, перехватчики axios добавляют `Authorization` и обрабатывают 401.
- Уведомления в `Layout` запрашиваются через `notificationsApi.getAll` и показывают список.
- Раздел "Обзор задач" (`ReviewsPage`) получает/обновляет данные через `reviewsApi`.
- Остальные разделы используют мок-стор (`useAppStore`) и не обращаются к реальному API: задачи, канбан, фильтры, финансы, аналитика, команда, дашборд берут статические массивы → фактически оторваны от бекенда.

## Что работает сейчас
- Авторизация/регистрация, загрузка текущего пользователя через `/auth/me`; редирект неавторизованных на `/login`.
- Переключение навигации, базовый лэйаут и выпадение списка уведомлений.
- Отображение мок-дашборда, канбана, задач, команды, финансов и отчётов (статические данные, без сетевых ошибок).
- Раздел Reviews: загрузка задач на проверку, подтверждение/отклонение (при наличии прав) через бэкенд.

## Что не работает / несоответствия
### Визуальные несоответствия Figma
- Логин/регистрация в тёмной теме, отсутствует монохромная палитра и фирменные отступы/радиусы из макета.
- Карточки, тени, шрифты и отступы частично не совпадают (радиусы 14px заданы в :root, но отдельные компоненты используют другие значения; шрифт Montserrat вместо требуемого Inter).
- Не реализованы все компоненты из макета: KPI/Chart в едином стиле, Timer card, Efficiency card, Avatar group вариации, модальное окно с анимацией и drag&drop-файлами.

### Функциональные проблемы
- **Dashboard**: данные жёстко захардкожены, KPI/графики не используют `/api/dashboard`; нет блока последних задач, таймера, эффективности команды.
- **Tasks**: фильтры "Мои/Важные/Выполнено" работают по мок-данным; нет связки с бекенд-фильтрами; нет приоритетов/дат/исполнителей/меню; создание задачи сохраняет только в локальный store.
- **Kanban**: статические задачи и статусы `BACKLOG/IN_PROGRESS/REVIEW/DONE`, которых нет в бекенде (у бекенда NEW/POSTPONED); drag&drop меняет локальный стейт, но не вызывает `/tasks/:id/status`; нет кнопки добавления, нет загрузки задач.
- **Team**: выводятся мок-пользователи без аватаров, ролей, статистики; нет поиска/фильтров; нет данных о задачах/часах.
- **Finance**: KPI/графики и список транзакций статичны, не используют `/transactions` и `/accounts`; нет выбора дат/категорий, нет лоудеров/ошибок.
- **Analytics/Reports**: данные захардкожены, игнорируют `/reports` и реальный набор метрик из бэкенда.
- **Модальное создание задачи**: отсутствуют поля даты, приоритет, статус, выбор исполнителей, drag&drop файлов; нет привязки к API; нет валидации и загрузки файлов в `/files/{taskId}`.
- **Интернационализация статусов**: фронт использует `BACKLOG` и не отображает `POSTPONED`; подписи и цвета не унифицированы.
- **Сетевые/консольные риски**: при обращении к разделам, которые сейчас используют мок-данные, сетевых ошибок нет, но это скрывает отсутствие интеграции; лоудеры/обработчики ошибок реализованы только частично (Reviews, Auth, Notifications).

### Производительность и качество кода
- Много дублирующих мок-структур вместо централизованного стора на основе API.
- TypeScript: используется `any` крайне редко, но отсутствуют интерфейсы для нескольких API-ответов (напр. Finance/Reports в UI), часть компонентов принимает `string` вместо строгих enum типов, нет DTO для форм.
- Лишние ассеты (`hero.png`, `vite.svg`, `react.svg`), неиспользуемые css-классы (dark-*) и классы tailwind, которые не определены в теме.
- Зависимости: установлен tailwind + lucide-react + zustand + recharts; нет явных лишних пакетов, но node_modules включён в репозиторий (хуже для скорости).

## Заключение — приоритеты исправления
1) Подключить все разделы к реальному API: задачи/канбан, дашборд, финансы, отчёты, команда, модалка создания задачи, загрузка файлов и drag&drop статусов.
2) Выравнять дизайн под Figma: единая монохромная тема (фон #f3–f6, белые карточки, радиусы 10–12px, Inter), корректные отступы, тени, hover/анимации, пиксельное совпадение компонентов.
3) Привести статусные/приоритетные enum'ы фронта к бекендовым (`NEW`, `IN_PROGRESS`, `REVIEW`, `DONE`, `POSTPONED`; `LOW…URGENT`) и пробросить их в фильтры/канбан/формы.
4) Добавить управление ошибками и лоудерами для всех сетевых вызовов; вынести базовые DTO и интерфейсы для Finance/Reports/Notifications.
5) Удалить мок-данные, перенести логику в store c серверным источником, убрать неиспользуемые ассеты и dark-тему в auth-экранах.
