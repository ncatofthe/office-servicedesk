# Отчёт о соответствии ТЗ
Статусы: [✅] выполнено, [⚠️] частично, [❌] не выполнено.

## 1. Общая информация
- [⚠️] Базовые возможности (создание/назначение/статусы/сроки/комментарии/файлы/отчёты) поддержаны в бэкенде, но фронтенд использует мок-данные и не подключён к API для задач, файлов, аналитики.

## 2. Роли пользователей
- Admin: [⚠️] Роли и проверки есть в бэкенде; во фронте нет UI для управления пользователями/справочниками, маршруты не ограничены по ролям (кроме Reviews)
- Manager: [⚠️] Бэкенд разрешает создание/редактирование/назначение/статусы; фронтенд канбан/форма не связаны с API.
- Employee: [⚠️] Бэкенд ограничивает статусы; фронтенд не учитывает; задачи не фильтруются по пользователю.
- Finance: [⚠️] Бэкенд есть; фронтенд Finance не подключён к API.
- Viewer: [⚠️] Роль есть; фронтенд нет read-only ограничений.

## 3. Разделы системы
### 3.1 Dashboard
- KPI (отложенные/в процессе/завершенные/рейтинг): [⚠️] рендерятся, но на мок-данных, без API.
- Графики продуктивности/производительности: [⚠️] есть статичные графики, без данных с сервера.
- Блок сотрудники/работник месяца/бюджет: [⚠️] отображаются статично, без связи с API.

### 3.2 Создать задачу (модалка)
- Поля (название, дата, описание, приоритет, статус, исполнители, файлы drag&drop): [❌] есть только название/описание, без дат/приоритета/статуса/исполнителей/файлов; нет drag&drop; не пишет в бекенд.
- Кнопки Сохранить/Отмена: [⚠️] есть, но сохраняет лишь в локальный стор.
- Появление задачи в канбане: [❌] не синхронизируется с сервером.

### 3.3 Задачи (Kanban)
- Фильтры (Все/Мои/Срочные/Архив): [❌] есть частично (Все/Мои/Важные/Выполнено) и работают на мок-данных.
- Колонки (Бэклог, В процессе, На проверке, Завершенные): [⚠️] 4 колонки есть, но статусные значения не совпадают с бэкендом (BACKLOG вместо NEW, нет POSTPONED).
- Карточка содержит все поля: [❌] нет даты/приоритета/комментариев, прогресс только мок, нет меню.
- Drag&drop между колонками: [⚠️] работает локально, не вызывает API.
- Добавление/редактирование/просмотр: [❌] добавление в стор; редактирования/просмотра нет.

### 3.4 Команда
- Карточка (фото, имя, должность, локация, навыки, задачи, часы): [❌] только имя/роль/счётчик задач; остального нет.
- Поиск/фильтрация/просмотр/добавление: [❌] отсутствуют.

### 3.5 Обзор задач (Review/выплаты)
- KPI (на рассмотрении/подтвержденные/выплаты/участники): [⚠️] первые три отображаются на основе `/reviews`; участники проектов отсутствуют.
- Статусы задач, подтверждение/отклонение: [✅] реализовано через `reviewsApi.update` при наличии прав.
- Просмотр деталей задачи: [❌] нет перехода к задаче.

### 3.6 Оплата (Finance)
- KPI (потрачено/заёмные/платежи/оборот): [❌] статичные цифры, не из API.
- История транзакций, график по месяцам, продажи по категориям: [⚠️] графики есть, но на мок-данных; нет реальных транзакций.
- Реквизиты, планируемые платежи: [❌] отсутствуют.

### 3.7 Отчёты (Analytics)
- KPI (рейтинг выполнения/невыполнения/экон.эффективность/активность): [❌] другие KPI на мок-данных.
- Графики (дедлайны, эффективность, затраты по отделам, активность по месяцам): [⚠️] есть графики, но не совпадают по составу и не подключены к `/reports`.

## 4. Сущности БД
- Модели и связи из ТЗ присутствуют в `schema.prisma` (User, Task, TaskStatus/Priority, Assignee, Comment, Attachment, Review, Transaction, Account, Notification, History): [✅].

## 5. API
- Большинство маршрутов из ТЗ реализованы (auth, users, tasks, comments, files, reviews, finance, dashboard, reports): [✅] в бэкенде. Фронтенд использует только часть (auth/notifications/reviews): [⚠️].

## 6. Основные функции
- Создание/редактирование/назначение/изменение статусов/drag&drop/комментарии/файлы/выплаты/отчёты: [⚠️] сервер поддерживает, фронтенд покрывает частично (нет drag&drop к API, нет файлов/комментов в UI, выплаты/отчёты не отображаются).

## 7. Сценарии использования
- Цепочка менеджер→исполнитель→проверка→выплата→отчёты: [⚠️] реализуема на сервере, но UI не проводит пользователя по сценарию (нет связи канбана с review, нет выплат/отчётов на UI).

## 8. Требования к фронтенду
- Адаптивность: [⚠️] сетки реагируют, но без теста под брейкпоинты и без соответствия макету.
- Kanban drag&drop: [⚠️] локально работает, нет связи с API.
- Фильтры/поиск: [⚠️] частично в Tasks; нет глобальных и нет связки с API.
- Модальные окна: [⚠️] есть базовое модальное без анимации/drag&drop.
- Графики: [✅] реализованы через Recharts (мок-данные).
- Уведомления: [⚠️] выводятся, но нет отметки прочитанного/нагрузочного теста.

## 9. Требования к бэкенду
- REST API, авторизация, роли, CRUD задач, загрузка файлов, история изменений, агрегации для отчётов: [✅] реализовано.

## Противоречия/замечания
- Терминология колонок канбана в ТЗ ("Бэклог") не совпадает со статусами в БД (`NEW`/`POSTPONED`). Требуется согласовать отображаемые названия и маппинг.
- В ТЗ запрошены поля локации/часы в карточке сотрудника — в БД таких полей нет; нужны новые атрибуты или расчётные поля на фронте.
