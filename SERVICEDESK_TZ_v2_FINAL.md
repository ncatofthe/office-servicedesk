# ТЗ ServiceDesk v2

Актуально на 2026-04-23.

## Видение

Система должна стать основным рабочим инструментом отдела поддержки и смежных офисных процессов. В первой версии продукт заменяет Freshdesk-подобный поток заявок, но остаётся настраиваемым под одну компанию и локальный сервер.

Компания занимается оптовой торговлей, закупками из Китая, складом, отгрузками, возвратами и продажами через Ozon/Wildberries. Поэтому ServiceDesk покрывает не только IT, но и операционные заявки: склад, товарооборот, маркетплейсы, возвраты, документы и внутренние обращения.

## Пользователи

- Заявитель: сотрудник, склад, внешний контрагент или клиент.
- Исполнитель: аналитик 1С, 1С-разработчик, системный администратор, складской администратор, серверный администратор.
- Администратор портала: настраивает справочники, пользователей, папки и команды.
- Наблюдатель: архивная read-only роль для просмотра без права изменения.

## Основной поток заявки

1. Пользователь создаёт заявку через веб или в будущем через email.
2. Обязательные поля: название и описание.
3. Система автоматически присваивает заявке понятный номер в стиле service desk/Freshdesk, чтобы сотрудники могли быстро ссылаться на обращение в переписке и устной коммуникации.
4. Дополнительные поля: папка, тип, подтип, сущность, приоритет, вложения, исполнители.
5. Заявка попадает в папку/очередь.
6. Исполнитель берёт заявку, ведёт переписку, прикладывает файлы и меняет статус.
7. При необходимости заявки связываются или объединяются.
8. Заявка закрывается; для объединённых задач с несколькими исполнителями требуется согласованное закрытие.

Для режима `UNION` действует отдельное правило: master и child должны восприниматься сотрудниками как одна заявка. Это значит, что child использует номер master-заявки, не дублируется отдельной карточкой в основной очереди и автоматически следует за статусом master.

## Справочники

- Папки: IT, 1С, склад, маркетплейсы, документы, операции и любые новые направления.
- Сущности: принтер, 1С, удалёнка, заказ, отгрузка, возврат, маркетплейс и другие объекты.
- Типы: проблема с периферией, доступы, ошибка 1С, складская операция, возврат, отгрузка.
- Подтипы: полностью настраиваемые администратором.
- Команды: группы исполнителей, привязанные к папкам.

## Роли и доступ

- Заявитель видит свои заявки и может создавать новые.
- Исполнитель работает с очередью, комментариями, статусами и базой знаний.
- Администратор управляет справочниками и пользователями.
- Наблюдатель читает данные без права изменения.

## Email

Целевой канал - Яндекс IMAP/SMTP. Backend MVP уже умеет через IMAP создавать заявку от аккаунта, привязанного к email. Если аккаунта нет, создаётся внешний `REQUESTER` по почте, а администратор сможет позже уточнить профиль. Для проверки есть `email:smoke`, для реального ящика - `email:sync`, для 24/7 polling - `EMAIL_INTAKE_ENABLED=true`.

SMTP-ответы добавлены как backend MVP: `POST /api/tasks/:id/email-reply`, dry-run по умолчанию при `EMAIL_OUTBOUND_ENABLED=false`, threading через последний `EmailInboundMessage`. Осталось: ручная проверка на корпоративном Яндекс-сервере, UI-кнопка ответа, журнал исходящих писем, retry и UI-настройки ящика.

## База знаний

Есть MVP базы знаний: CRUD статей, поиск, категории, опубликованные/черновики, страница `/knowledge`. Исполнитель может найти статью в карточке заявки и вставить markdown-ссылку в комментарий.

## Бэкапы

Цель: ежедневный backup всей БД в 03:00, хранить последние 2 дня, старые удалять. Backend уже поддерживает ручные команды `backup:create`, `backup:list`, `backup:cleanup`, `backup:restore` и плановый scheduler при `BACKUP_ENABLED=true`. Backup лежит в корневой папке проекта `backups` по умолчанию.

Осталось для полноценного продукта: отдельный backup пользовательских файлов из `task-manager-backend/uploads`, админский UI/инструкция восстановления и регламент проверки restore на тестовой базе.

## Критерии релиза первой версии

- Пользователь может создать заявку и видеть свои заявки.
- Исполнитель может вести очередь, комментировать и менять статус.
- Админ может настроить папки, типы, подтипы, сущности и команды.
- Работают вложения и базовый поиск/фильтры.
- Работают LINK/UNION слияния и согласованное закрытие на backend.
- Работает ручной backup БД и есть возможность включить daily scheduler.
- Работает backend MVP создания заявки из email.
- Работает backend MVP email-ответа в dry-run и threading.
- Работает MVP базы знаний.
- Проект стабильно стартует на локальном сервере компании.
